AMBIENTE ISOLADO

Kaggle como bancada de testes

Todo teste que exige execução de scripts Python, embeddings, GPU ou motores locais deve acontecer em notebooks do Kaggle. A infraestrutura de produção da AWS permanece intocada.

Novo notebook Explorar notebooks

Atalho por projeto

Abra uma busca de notebooks no Kaggle para o projeto selecionado. Se o catálogo tiver uma URL própria, ela será usada como atalho direto.

Checklist de isolamento

  • 01 Usar apenas notebooks descartáveis do Kaggle.
  • 02 Nunca colar credenciais AWS, chaves privadas ou tokens de produção.
  • 03 Ativar GPU somente quando o teste exigir processamento gráfico.
  • 04 Salvar uma versão do notebook ao final de cada bateria.
  • 05 Registrar o resultado no painel e colar o link do notebook.
Guia completo de sandbox

Gerenciador de URLs e atalhos

sobrescreve sem tocar no código

Edite o JSON indexado pelo id numérico do projeto. Campos aceitos: repoUrl, demoUrl, videoUrl, kaggleUrl, embedUrl e embeddable. No servidor, os dados vão para reports/url-overrides.json; no modo estático, ficam no localStorage.

Portabilidade do catálogo

O catálogo vive em projects.json. Para adicionar ou remover projetos, edite esse arquivo. Os botões abaixo exportam e importam o catálogo atual.

Como gerar uma nova instância

O template inclui o script scripts/create-instance.js. Copie o molde, injete um novo projects.json e publique o resultado como DragonZord Teste N.

node scripts/create-instance.js ../meu-novo-zord ../catalogos/meu-catalogo.json
